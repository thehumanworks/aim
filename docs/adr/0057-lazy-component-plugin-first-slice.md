# ADR 0057: Load capability-scoped components only when called

- Status: Accepted
- Date: 2026-09-25
- Baseline: 0005, 0008, 0016, 0017, 0027
- Scope: First `aim:plugin@0.1.0` tool-host slice, source/trust formats, resource reads and session composition; not the QuickJS script runtime, declarative UI rendering, network egress or model-provider plugins.

## Context

ADR 0016 selects Wasmtime components, per-hash grants and a synchronous guest world. The extensibility research §B measures pooled instantiation and calls for one engine, bounded stores and source-only compilation. [Wasmtime 48.0.3](https://github.com/bytecodealliance/wasmtime/releases/tag/v48.0.3) is an LTS patch release with fuel accounting fixes. Its compiled-component deserialization API is `unsafe`, while aim forbids unsafe code. The first plugin tool must also be advertised before the first model request without compiling Wasmtime on that startup path.

The session host already composes workspace, media and extra tools, then narrows them by the named agent's tool allowlist (`crates/aim/src/host.rs`, ADR 0050). A nested plugin call must use that narrowed dispatcher, or the guest could reach a tool its agent cannot call. Project plugins must be read through the workspace for SSH/remote shadowing (ADR 0014); the existing text-only `Files` method cannot carry a component.

## Decision

- Pin Wasmtime and its restricted WASI P2 host to `=48.0.3` with minimal component, Cranelift, pooling and async features. An `Engine` is created once per process, lazily on a background worker after a session with admitted plugins starts. The first model request never awaits compilation; a first plugin call compiles if warming is incomplete. The guest receives no preopened directories, inherited arguments, environment, stdio, process or network access. A call has 20 million fuel, a 64 MiB memory limit and a 30-second wall deadline. The host compiles source in a blocking worker and caches the compiled component in memory by component SHA-256, Wasmtime version and engine-limit configuration.
- Do not read or write `.cwasm` on disk in this slice. The persistent cache chosen in ADR 0016 remains a goal, but safe reuse needs an upstream safe deserialization API or a maintainer-approved, narrowly audited unsafe exception with cached-file integrity checks. Untrusted downloaded precompiled images are never loaded.
- Freeze the WIT package `aim:plugin@0.1.0` and its `extension` world: synchronous guest exports `init`, `call-tool`, `on-event`, `run-command`, `complete`, `shutdown`; host imports `host`, `kv`, `tools`, `session`, `ui`, `bus`. Record/variant shapes remain fixed in the 0.1 track, with the `ext` action for additions. The first slice runs registered tools; UI/bus return denials, and `session.query` exposes only bounded read-only session metadata under a `session.read` grant. A guest importing `wasi:http` fails linkage; no HTTP egress is available. A typed `wasi:http` deny adapter remains for the next slice.
- `aim-plugin.toml` declares `name`, `version`, `api = "0.1"`, component path, requested capabilities and bounded `[[tools]]` descriptions/schema. The manifest advertises tools without compiling the guest. On the first call, `init` must return the same tool registration or the call fails. Guest tool names are exposed as `plugin__<plugin>__<tool>`.
- `~/.aim/trust.toml` records granted capability strings against a domain-separated SHA-256 hash of the canonical manifest (normalized record fields and JSON tool schemas) plus component bytes. The compiled-code cache separately keys the component bytes. Grant updates reload under a stable private file lock and atomically replace the owner-private registry, so stale issuers cannot restore a revoked grant. Global `~/.aim/plugins/<name>` directories are discovered by default but obtain no import grant automatically; project `.agents/plugins/<name>` components are inert until their exact hash is trusted. `aim plugin install|list|trust|untrust` manages the global files and grants; `list` and `trust` accept `--project ROOT` with optional `--ssh` or `--remote` and read the project through aimx. Install does not overwrite an existing plugin. Semantic manifest edits or component edits get a new trust hash and no inherited grants.
- Add `Files::read_binary` as a bounded whole-file workspace read for project components (2 MiB cap); retain existing text reads. Global installed components have a 16 MiB cap. A plugin's durable KV belongs to its component hash, with owner-private storage, a stable lock and atomic writes. Missing grants return denied results. Guest `tools.call` checks its `tools.call:<glob>` grant and the agent-allowlist-narrowed host before delegation; nested calls carry deterministic idempotency keys derived from the outer call.
- Add one optional plugin factory seam in `NativeServices` after `with_extra_tools`. It receives the workspace-backed project files and a delegate narrowed by the agent's allowlist. The final composed host is still narrowed for the model, so both outer plugin tools and nested calls obey the session ceiling.

## Consequences

The ordinary no-plugin path does not initialize Wasmtime. A plugin's first tool call pays compilation once per process, and changing its source or engine limits changes the cache key. No agent-authored component can grant itself capabilities by changing its manifest or calling a tool outside the session ceiling. The checked-in Rust/WASIp2 examples and SDK make the ABI reproducible without compiling guests in the routine workspace gate. Persistent compiled-code reuse, typed HTTP denial, QuickJS scripts and UI-surface/event composition remain separate work.

## Verification

`crates/aim-plugin/tests/host.rs` exercises missing grants, edited-hash trust, KV persistence and concurrent updates, delegated calls through both grant and allowlist, cache identity, and a real runaway WASIp2 guest fuel trap. `crates/aim/src/resources/files.rs` and `crates/aim/tests/resources.rs` cover binary workspace reads and the nested allowlist seam. `plugins/examples/build.sh --verify` rebuilds the checked-in components and checks their SHA-256 digests. The W27 handoff report records the final integrated gate, cost measurements and a real OpenRouter turn using a composed plugin tool.
