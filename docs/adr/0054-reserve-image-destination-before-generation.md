# ADR 0054: Reserve image destinations before paid generation

- Status: Accepted
- Date: 2026-09-25
- Baseline: 0008, 0021, 0022, 0042, 0046
- Scope: Harness file reservation and media image persistence; not provider billing, format selection, or a general overwrite lease.

## Context

FIX12 and REV9 found that `generate_image` pays the provider before its `IfAbsent` write can reject an existing file or a read-only grant. A read or a path syntax check is not an authority-equivalent preflight because it cannot atomically claim the destination. ADR 0046 requires every actionable harness method to carry per-call authority and respect the session ceiling.

## Decision

Add `fs.reserve {workspace, path, if_absent, idempotency_key, scope}` returning an opaque reservation, and `fs.finalize` / `fs.cancel` with the same workspace, key, and optional scope. Only `if_absent: true` is supported; false receives `invalid_params`. An overwrite reservation would need an explicit precondition and must not silently replace a user's file. All three calls enforce the effective W20 authority. The reservation is bound to the authenticated session and workspace. A later finalize or cancel must retain write permission under the then-current scope. The file backend used at reservation retains the earlier scoped grant, so a later call cannot widen it.

The local backend atomically writes a unique marker at the target with `IfAbsent` through descriptor-confined filesystem operations. Existing files, write-denied paths, and protected paths refuse reservation before the provider call. Finalize atomically replaces the marker under its whole-file hash precondition. Cancel removes the marker only while its hash matches, so ordinary intervening writes survive. A successful finalize or cancel consumes the reservation. A session holds at most 64 reservations; its expiry cleanup cancels remaining markers. An expired or unknown handle cannot finalize. The marker is random and unique, but a caller able to read and deliberately replace it with exactly the same bytes can defeat hash-only identity checking; this contract does not claim adversarial inode ownership against another actor with equal workspace authority.

`ToolHost::reserve_blob` defaults to `unavailable`; its finalize/cancel counterparts also default to `unavailable`. Harness-backed hosts implement the three methods. `generate_image` validates the requested path, reserves it, then calls the provider. It cancels on provider failure, oversized output, or finalize failure. A default path is chosen before generation with a format-neutral `.img` suffix because the MIME type is not known yet. A refused reservation never invokes the provider. Generated bytes are not retried at another path after a reservation collision, since the collision is known before payment.

## Consequences

The reservation marker is briefly visible on disk. The server's session reaper removes abandoned markers after its resume TTL; a server crash or failed cleanup can leave one, and a same-byte malicious replacement is not distinguished by its hash. Normal writes still use their existing preconditions. The reservation protocol has separate idempotency keys for reserve, finalize, and cancel so transport retries cannot duplicate a mutation.

## Verification

Aimx conformance tests exercise existing-file and read-only refusal before the provider boundary, finalize/cancel, and unchanged marker cleanup. Media tests count provider calls and verify that both refusals occur before generation and that provider failure cancels. `mise run check` and serial live smoke remain the integration gates under ADR 0022; this ADR's contract alone does not establish a live provider or SSH result.
